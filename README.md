# Schedule Maker

Модульная система автоматического составления расписания занятий вуза.

Программа рассчитана на реальные, а не учебные требования: преподаватель-вахтовик,
которому нужно три дня строго подряд; «мигающее» расписание раз в две недели;
преподаватель, который может только по субботам; поток биологов, который нельзя делить
на подгруппы; занятие, жёстко привязанное к 15:30; зависимость от расписания стороннего
колледжа; филиалы в разных городах со своими звонками.

## Чем отличается от аналогов

**Каждое правило — отдельный модуль.** Новое требование добавляется плагином, а не
правкой ядра. Набор включённых правил, их жёсткость и веса хранятся в базе, поэтому
«у биологов в Махачкале нельзя делить группу» — это настройка, а не программирование.
Ядро не знает ни одного плагина по имени: оно читает точки входа и подключает всё,
что найдёт.

**Программа объясняет отказ.** Главная слабость существующих решений — молчаливое
«решение не найдено». Здесь работают две вещи:

* *предпроверка* до запуска — арифметика, которая ловит заведомо невозможное:
  «Иванову И. И. нужно поставить 10 пар, а в его доступные дни (пн, сб) помещается 8.
  Выделите ещё 1 день или снимите 2 пары»;
* *диагностика* после — статистика отказов по каждому правилу: «из 252 рассмотренных
  вариантов 14 отпало по доступным дням преподавателя, 12 — он занят, 10 — не нашлось
  аудитории на 30 мест».

**Два уровня доступа.** Студенты и преподаватели смотрят расписание по обычной ссылке
без пароля; создаёт, правит и публикует его только администратор.

## Быстрый старт

```bash
pip install -e ".[dev]"

schedmaker init-admin --username admin      # создаст базу и спросит пароль
schedmaker demo-data --scenario mahachkala  # демонстрационный филиал
schedmaker serve                            # http://localhost:8000
```

* `http://localhost:8000/` — публичное расписание, пароль не нужен.
* `http://localhost:8000/admin` — панель управления.

Точный решатель на OR-Tools ставится отдельно: `pip install "schedule-maker[cpsat]"`.
Без него программа работает на встроенном жадном алгоритме.

## Команды

| Команда | Что делает |
|---|---|
| `schedmaker init-admin` | создаёт базу и учётную запись администратора |
| `schedmaker demo-data` | заполняет базу демонстрационным филиалом |
| `schedmaker serve` | запускает веб-приложение |
| `schedmaker check` | предпроверка выполнимости без генерации |
| `schedmaker generate` | составляет расписание из командной строки |
| `schedmaker import ФАЙЛ` | разбирает нагрузку из Excel или CSV |
| `schedmaker export-data` | снимок опубликованных расписаний в JSON |
| `schedmaker build-site` | собирает статический сайт для публикации |
| `schedmaker plugins` | показывает подключённые расширения |

## Что умеет

*Данные.* Филиалы со своими звонками, группы и подгруппы, преподаватели с белыми и
чёрными списками дней, дисциплины, аудиторный фонд, учебная нагрузка. Импорт из
Excel и CSV с автоматическим угадыванием колонок и предпросмотром до записи.

*Составление.* Расстановка от самых стеснённых требований к самым свободным: сначала
«субботники» и приезжие, свободными преподавателями затыкаются оставшиеся окна.
Два алгоритма на выбор — встроенный жадный и точный на OR-Tools CP-SAT.
Результат воспроизводим: одно и то же зерно случайности даёт одно и то же расписание.

*Ручная правка.* Доска с перетаскиванием: при захвате пары зелёным подсвечиваются
клетки, куда её можно перенести без нарушений. Перенос в любую другую клетку тоже
разрешён — программа не запрещает, а называет цену. Закреплённые пары переживают
перегенерацию.

*Работа с изменениями.* Замены преподавателя, аудитории и переносы на конкретную дату
поверх основного расписания; студент видит пометку на своей странице.

*Выгрузка.* Календарь `.ics` (пары раз в две недели выгружаются с правильным
повторением), Excel, страница для печати и сохранения в PDF, машинный JSON.

*Отчёты.* Выполнение нагрузки преподавателей, загрузка аудиторного фонда.

## Как написать своё правило

Скопируйте `examples/plugin_template`, опишите класс-наследник `BaseConstraint`
и объявите его в `pyproject.toml` своего пакета:

```toml
[project.entry-points."schedmaker.constraints"]
my_rules = "my_package.rules:register"
```

После `pip install` правило появится на странице «Правила» — ядро менять не нужно.
Подробности и полный список точек расширения — в `examples/plugin_template/README.md`
и в `docs/ARCHITECTURE.md`.

## Публикация расписания для студентов

Администратор работает с программой у себя, а студентам нужна страница, которая просто
открывается и не может упасть. Поэтому опубликованное расписание превращается в набор
обычных HTML-файлов:

1. в панели управления нажать «Опубликовать», затем «Снимок для сайта»;
2. положить полученный `timetable.json` в репозиторий как `data/timetable.json`;
3. `git push` — сборка соберёт статический сайт и выложит его на GitHub Pages.

Сервер для этого не нужен, и взламывать там нечего.

## Разработка

```bash
ruff check . && ruff format --check .
pytest
```

Единый рабочий процесс `.github/workflows/ci-release.yml` на каждый push и pull request
гоняет линтер и тесты, на push в `main` пересобирает и публикует сайт, а на тег `v*.*.*`
дополнительно собирает `.exe` для администратора и создаёт релиз.
